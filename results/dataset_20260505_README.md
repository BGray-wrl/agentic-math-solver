# Agentic Math Solver — Master Dataset (2026-05-05)

Generated by `experiments/export_dataset_20260505.py` from the full set of 0-7-rubric
experiments run between 2026-03 and 2026-05-05.  Every trial is judged by up to three
independent judges (`deepseek-v4-pro`, `gemini-3-flash-preview`, `deepseek-v4-flash`),
exposed under a unified `judges` schema for direct cross-judge comparison.

This dataset supersedes `dataset_20260504.jsonl` (Phase 1 only, two judges).

## Focused bucket views (added 2026-05-07)

For most analysis tasks the master JSONL is more than you need. The bucket
sub-datasets below are filtered + transformed views of this master, each with
its own data dictionary, summary CSV, and report:

- **`results/architecture_20260506/`** — cross-mode, cross-model architecture
  comparison (sources: phase1, phase1_reasoning, phase2, phase3,
  gpt5_nano_pass3). Canonical judge: v4-flash. Includes a derived
  `pass_at_1_v4flash` column for generate-mode rows.
- **`results/scaling_20260506/`** — best-of-N curves with **bootstrap-resampled
  pass@n** instead of nested-prefix pass@n (sources: scaling, scaling_reasoning,
  scaling_v4flash). One row per (model, problem, n).
- **`results/roleswap_20260506/`** — cross-model role-assignment matrix
  (sources: roleswap, roleswap_reasoning, flex_cross_ideator with
  `subclass="ideator_strength"`).

All three buckets are enriched with:
- `difficulty` ∈ 0..5 (0=pre-IMO, 1=IMO-tier, 2=research-easy, 3=research-medium,
  4=research-hard, 5=research-frontier) — see `experiments/difficulty_20260506.py`
- `is_26_research` (bool) — True for the 10 problems in the 2026 research-tier
  set (renamed from `is_special_10`)
- `reasoning` ∈ {`default`, `max`, `min`} — uniform label of the reasoning
  configuration intent across providers (most rows are `default`; `max` is the
  set of explicit-reasoning experiments; `min` is reserved)

The `flex_strong_critic`, `flex_passn`, and `flex_composed_critic` rows remain
in the master JSONL only — they're outside the three thematic buckets and are
not in any sub-dataset for this pass.

### `judges.<j>.source` values

The `source` field tells you which run produced that judge score.  Useful when auditing
multi-stage regrades or choosing which judge call to trust.

| Source string | Meaning |
|---|---|
| `phase1_inline` | v4-pro score from the original Phase 1 run (`seed_ideas_full_compare`) |
| `phase1_inline+parsefail_patch` | Phase 1 v4-pro recovered from a re-judge of a parse failure (16 cells fixed) |
| `regrade_gemini_20260504` | gemini-3-flash trial-level regrade of Phase 1 best_solutions |
| `regrade_branches_gemini_20260504` | gemini-3-flash per-branch regrade of Phase 1 generate / seed_generate |
| `phase2_inline` / `phase3_inline` / `roleswap_inline` | gemini score from the original run |
| `regrade_phase2_full_v4pro_20260505` | v4-pro re-judge of all 140 Phase 2 best_solutions |
| `regrade_phase2_v4pro_frontier_20260505` | v4-pro re-judge of the 10 Phase 2 frontier-flagged branches |
| `regrade_phase3_v4pro_truncated_20260505` | v4-pro re-judge of Phase 3 (with reasoning-budget fix) |
| `roleswap_v4pro_escalation` | v4-pro escalation on special-10 hits in role-swap |
| `scaling_inline_phase1_reuse` / `scaling_inline_fresh` | inline judges from the scaling run |
| `regrade_v4flash_20260505` | this build's v4-flash third judge |

## NAs

- **Errored / missing trials**: rows are emitted with `error="trial_missing"` (or the
  original error string) and `final_solution=null`, all judge scores `null`.  4 such
  trials in Phase 1 (deepseek-v4-pro PB-Basic-028/030 timeouts), 1 in Phase 3
  (`first-proof-4-official` got stuck for 4h and never completed).
- **Missing v4-flash scores**: v4-flash regrade is the new addition.  If a cell's
  v4-flash call hit the cumulative cost killswitch or returned a parse failure, its
  `judges.v4flash` entry has `score=null` (and `source=null`).  See
  `experiments/results/v4flash_judge_20260505/` for the per-call audit trail.
- **Phase 2 v4-pro per-branch coverage** is incomplete by design — only the 10
  frontier-flagged branches were regraded with v4-pro.  Other branch rows have
  `judges.v4pro = {null, null, null}`.
- **Phase 3 has no per-branch v4-pro** — only trial-level was regraded.
- **Roleswap v4-pro is special-10 only** — most cells have `judges.v4pro = null`.
- **Scaling has no trial-level final_solution / judges** — trial wrappers exist solely
  to group branches.  Compute best-of-N off `branches[].judges`.
- **Full mode (Phase 1) has trial-level judges only** — the single branch's `judges`
  dict is a copy of the trial's, kept for consumer convenience.

```python
rows = [json.loads(l) for l in open("results/dataset_20260505.jsonl")]

# Filter by experiment
phase1 = [r for r in rows if r["experiment"] == "phase1"]

# Triple-judge agreement on a single trial
```

## Aggregation recipes

**Mean v4-flash score per (model, mode) on Phase 1:**
```python
import statistics
sub = [r for r in rows if r["experiment"]=="phase1" and v4f(r) is not None]
by_cell = {}
for r in sub:
    by_cell.setdefault((r["model"], r["condition"]), []).append(v4f(r))
for cell, scores in sorted(by_cell.items()):
    print(cell, round(statistics.mean(scores), 2), len(scores))
```

**Phase 1 v4-pro means with parse-failure patches applied** (recovers the +0.07
gemma generate / +0.03 gemma seed_generate corrections from agent_log.md's audit
closure).  Trial-level `judges.v4pro` reflects the original Phase 1 pick; per-branch
`branches[].judges.v4pro` includes the patches.  To get the patch-corrected
trial-level mean, max over branches:

```python
import statistics
from collections import defaultdict
acc = defaultdict(list)
for r in rows:
    if r["experiment"] != "phase1" or r.get("error"): continue
    if r["condition"] == "full":
        s = r["judges"]["v4pro"]["score"]   # full has 1 branch == trial; patches apply at trial
    else:
        # generate / seed_generate: max over patched per-branch v4pro
        bs = [b["judges"]["v4pro"]["score"] for b in r["branches"]
              if b["judges"]["v4pro"]["score"] is not None]
        s = max(bs) if bs else None
    if s is not None:
        acc[(r["model"].split("/")[-1], r["condition"])].append(s)
for k, v in sorted(acc.items()):
    print(k, round(statistics.mean(v), 2), f"n={len(v)}")
```

**Triple-judge confusion (where all three scored):**
```python
from collections import Counter
both = [(v4pro(r), gem(r), v4f(r)) for r in rows
        if v4pro(r) is not None and gem(r) is not None and v4f(r) is not None]
print(f"n={len(both)}")
print("v4pro vs v4flash exact match:",
      sum(1 for a,_,c in both if a==c) / max(len(both),1))
```

**Best-of-N on the scaling experiment under each judge:**
```python
import statistics
```

## Cautions

- Solution texts can be 5-50 KB.  Verdict texts can be 1-50 KB.  File is ~250 MB.
- Costs in the per-row `cost_usd` are **gen-side only** (model-under-test).  Judge
  costs are not in the row — they live in:
  - `experiments/results/v4flash_judge_20260505/<...>__*.json` (v4-flash, ~$50 total)
  - `experiments/results/regrade_phase2_full_v4pro_*.json`, `regrade_phase3_v4pro_*/`,
    etc. (v4-pro regrades, see agent_log entries)
  - Phase 1 v4-pro inline judge tokens are inside each Phase 1 trial's `calls` array
    (not in this dataset; consult source dirs).
- All scores are 0-7 IMO rubric.  Pass threshold used in agent_log.md headlines: ≥6/7.
- The v4-flash judge was validated against human grading on a 200-sample subset
  (gradingbench): r=0.76, 79% recall, 81% precision (see agent_log entry around line
  1847).  v4-pro gradingbench: r=0.79.  gemini-3-flash gradingbench: r=0.51.
