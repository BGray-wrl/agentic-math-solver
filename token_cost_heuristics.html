Pipeline token & cost heuristics

Ballpark figures for running one math problem through the generator → verifier↔reviser → judge pipeline. Order-of-magnitude only (assume ±2–3×).

The one thing that matters: turning reasoning ON inflates total output tokens ~10–50× (a generation goes from ~1.5K to ~15–100K, depending on the model). Everything else — extra stages, pass@k — is just a linear multiplier on top.

tokens ≈ k (passes) × F (stage factor) × G (output tokens / generation)
cost ≈ tokens × ($ per 1M output tokens)

F = 1 for generate-only, ≈ 2 for the full pipeline. Input tokens are small (~2K/call) and rounding error next to reasoning output, so the headline is driven by output. Output = visible answer + hidden reasoning tokens (see table).

gemma does reason hard (~14K hidden tokens/call) — the visible answer just stays short. That's why its quality jumps with reasoning on (pass@1 0.88 → 1.92) even though the answer length barely changes. "default" effort on deepseek-v4 / gpt-5.4 is not off. Some providers fold reasoning into completion_tokens ("folded in"); others report it separately — either way it's billed.

Rule of thumb for a full benchmark: × 70 problems. e.g. full pipeline, pass@3, gpt-5.4 ≈ $200 per sweep; gemini-3.1-pro ≈ $108; kimi-k2.6 ≈ $42. Generate-only is ~half these.

Where these come from. Reasoning-OFF per-stage tokens: 157 per-call pipeline logs (gemini-flash-lite / deepseek-v3.2). Reasoning-ON per-call output (visible + hidden): measured completion_tokens + reasoning_tokens in the KLT iteration logs. Frontier per-generation tokens & prices: expensive-models AnswerBench-50 calibration + the 2026-05-07 pricing snapshot — cost there reconciles to the cent against completion × price, so those figures are solid.

Big caveats. (1) Reasoning tokens are billed but often invisible. Open models here report them in a separate reasoning_tokens field; counting only the answer text (or trusting a cost log that missed them — the KLT logs recorded gemma at $0) undercounts the real load by ~10×. (2) gpt-5.4 at default effort emits only ~3.5K out and underperforms badly — the table assumes the high-effort config you'd actually want. (3) "default" reasoning on deepseek-v4 / gpt-oss is already reasoning-heavy, not "off". (4) Long-tail runs can be 2–3× the mean — cap max tokens for budgeting.
